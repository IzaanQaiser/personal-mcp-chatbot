# Session Memory

## Purpose

Maintain continuity across conversations.

## Memory Types

### Short-Term Memory

Current conversation context.

Examples:

- active user request
- current plan
- temporary constraints

### Medium-Term Memory

Recent project/session context.

Examples:

- ongoing school week
- recent deadlines
- repeated scheduling issues

### Long-Term Memory

Stable user preferences.

Examples:

- preferred briefing style
- quiet hours
- preferred work blocks
- notification preferences

## Memory Rules

- Memory must be inspectable.
- Memory must be editable.
- Memory must be deletable.
- Do not store sensitive data unnecessarily.
- Do not fabricate memory.
- Store only useful memory.

## MVP

Store:

- chat session summaries
- user preferences
- active task context

Do not store:

- full raw conversation forever unless user enables it
